# 业务范围说明（Business Scope）

## 1. 业务场景定义
本项目选定的业务场景为“空气质量 / 天气联动分析看板”。系统围绕城市维度展示当前天气、空气质量与综合风险状态，帮助用户快速判断某城市当前环境是否处于关注区间，以及未来短期趋势是否存在异常变化。

## 2. 场景选择理由
### 2.1 与题目要求的匹配性
- 数据接口易获得：天气与空气质量公开 API 丰富且稳定。
- 算法接口好定义：风险评分、异常检测都适合抽象为独立服务。
- 工作流天然清晰：城市选择 -> 数据获取 -> 分析 -> 展示。
- UI 易展示：卡片、趋势图、标签、筛选器都适合 Figma 复用。
- 文档易沉淀：接口契约、工作流说明、测试案例都较容易标准化。

### 2.2 为什么优于其他候选方案
- 相比新闻舆情：数据结构更稳定，外部接口波动更小。
- 相比评论情感分析：数据采集链路更简单，合规风险更低。
- 相比图像识别：上传链路与文件处理复杂度更低，更稳妥。

## 3. 目标问题
用户通常只能看到单一天气信息或单一 AQI 信息，难以快速理解“当前环境风险是否需要关注”。本系统希望把天气与空气质量放在同一个分析面板中，通过规则评分与异常检测将数据转化为更容易理解的业务信号。

## 4. 业务能力范围
### 4.1 核心能力
- 基于城市获取天气数据
- 基于城市获取空气质量数据
- 标准化与整合多源数据
- 计算综合风险评分
- 识别异常指标或趋势异常
- 展示当前状态、趋势、预测摘要

### 4.2 用户可见能力
- 选择或切换城市
- 查看当前温度、湿度、风速、AQI、PM2.5 等指标
- 查看综合风险等级（低 / 中 / 高）
- 查看异常提示与原因因子
- 查看趋势图与未来 7 天概览

## 6. 主要用户流程
### 6.1 主流程
1. 用户进入看板页面。
2. 选择目标城市。
3. 系统触发工作流并并行获取天气 / AQI 数据。
4. 系统标准化数据并调用分析接口。
5. 前端展示风险评分、趋势和异常提示。

### 6.2 异常流程
- 若天气接口失败：展示 AQI 结果并提示天气数据不可用。
- 若 AQI 接口失败：展示天气结果并提示空气质量数据不可用。
- 若分析接口失败：展示原始数据，同时提示风险分析暂不可用。
- 若全部失败：展示统一错误页和重试操作。

## 7. 业务规则草案
### 7.1 风险评分规则
- 综合使用 AQI、PM2.5、PM10、温度、湿度、风速等指标。
- 风险评分输出为 0-100 分。
- 风险等级建议分为：
  - 0-39：低风险
  - 40-69：中风险
  - 70-100：高风险
- 所有权重和阈值均应配置化，不写死在前端。

### 7.2 异常检测规则
- 突变异常：某关键指标相较过去小时均值变化幅度过大。
- 极值异常：某指标超过预设阈值。
- 联动异常：天气变化与 AQI 同时进入高风险区间。

## 8. 业务边界
### 8.1 系统负责
- 获取并整合天气 / AQI 数据
- 调用算法服务产生可解释结果
- 提供统一前端展示
- 提供错误提示与降级逻辑

### 8.2 系统不负责
- 医疗建议
- 官方环保评估结论
- 精确气象预测科学建模
- 长周期历史治理分析

## 9. 验收视角
从业务范围角度，项目成功的判断标准包括：
- 用户可以完成城市选择与查询
- 系统可以生成综合风险结果
- 风险结果具备基本可解释性
- 页面展示清晰、状态反馈完整
- 工作流支持参数化配置
